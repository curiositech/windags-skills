# Market and research evidence

This comparison distinguishes behavior described by product documentation from findings tested in a research setting. Check platform and rollout scope before using a product behavior as a current competitive claim.

## Shipped and documented patterns

| Primary source and context | Documented behavior | Design inference for agent presence |
| --- | --- | --- |
| [Figma Spotlight](https://help.figma.com/hc/en-us/articles/360040322673-Present-to-collaborators-using-spotlight), collaborative desktop/web canvas | Avatar-based follow, a labeled canvas border, and a direct Stop following action. The shared view is the canvas, including its navigation. Spotlight separately lets someone present to others. | Adapt the visible camera relationship and escape hatch to Iris. A human presentation feature is an analogue for view state. Agent follow should begin with the observer’s explicit action. |
| [OpenAI dot](https://help.openai.com/en/articles/20001530-getting-started-with-your-dot), documented limited rollout | A customizable character or pet represents the assistant. On desktop, the cloud computer has separate Take over and Return control actions. On mobile it opens in the user’s control. Local computer access is a separate permission. | A character can identify the assistant while the surface independently displays control ownership and device permissions. Treat mobile ownership as an explicit design choice. |
| [ChatGPT Voice](https://help.openai.com/en/articles/20001274-chatgpt-voice), voice in ChatGPT apps | Mic permission, mute and end controls, text alongside spoken output in Live, and conversational interruption. The transcript can differ from audio. Eligible camera and screen-share flows are separately described for Advanced Voice. | Show capture state and captions alongside voice. Treat an interrupted utterance and its editable text record as different from a completed reply. |
| [Alexa voice-interoperability privacy and security guidance](https://developer.amazon.com/en-US/alexa/voice-interoperability/design-guide/privacy-security), physical-device guidance | Calls for clear listening indicators and a visibly different mic-off state. It describes limits on which invoked service receives speech. | Couple an embodied agent’s mic indicator to the capture state. Make the current recipient visible when more than one agent or service is available. |
| [Apple Human Interface Guidelines for motion](https://developer.apple.com/design/human-interface-guidelines/motion) and [notifications](https://developer.apple.com/design/human-interface-guidelines/notifications), native platform guidance | Treats movement as purposeful feedback with accessible alternatives and treats notifications as timely information delivered outside the active UI. | Motion can explain a spatial relationship. An asynchronous notification should carry the consequential event, its destination, and a privacy-safe preview. |
| [Android notification documentation](https://developer.android.com/develop/ui/views/notifications) and [notification permission](https://developer.android.com/develop/ui/views/notifications/notification-permission), native platform guidance | Android provides channels, lock-screen visibility controls, user controls, and a runtime posting permission on supported versions. | Map review, decision, and failure events to user-controllable categories. Preserve a durable in-app receipt when delivery is denied. |
| [WCAG status messages](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) and [animation from interactions](https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html), normative criteria and explanatory guidance | Status messages should be programmatically determinable without taking focus under criterion 4.1.3 (AA). Disabling nonessential animation from interactions is criterion 2.3.3 (AAA). | Announce meaningful state transitions through text or the relevant status semantics. Keep pointer samples and camera interpolation out of announcements. |

## Research prototypes

**Pointing at work.** Pointer Assistant tested proactive pointing in a financial budget-planning task with 220 participants. The authors reported lower task load, higher satisfaction, and more budget categories compared with the traditional passive chat condition. The result motivates a prototype that attaches guidance to the relevant object. Use a separate test for multi-agent work, mobile scrolling, and high-stakes actions. [Pointer Assistant, CHI 2025](https://dspace.mit.edu/entities/publication/2d5afdd2-7d23-4773-bce2-1461d335b2f0)

**Choosing when and how to appear.** Sensible Agent separated the suggestion from the way it was presented. In its ten-person within-subject study of staged AR scenarios, participants reported lower mental demand and preferred the design to a user-initiated, voice-controlled baseline. Interaction took longer, and usability score differences were not statistically significant. Since the prototype changed initiation and presentation together, test those factors separately when comparing quiet in-context cues with spoken interruptions on the web. [Sensible Agent, UIST 2025, authors’ research summary](https://research.google/blog/sensible-agent-a-framework-for-unobtrusive-interaction-with-proactive-ar-agents/)

## Apply the evidence without copying the metaphor

On Eigenstory’s case-study canvas, a colored marker can identify the exact paragraph Edie is discussing. A persistent avatar can identify her in the conversation. The document remains usable when both visual elements are hidden. A synchronized collaborator pointer is optional, and a semantic link to that paragraph still works on a phone or in a screen reader.

A live cursor requires a live source of target events. A prerecorded sequence can show the same actor and pointer, with “Playing example” and a playback timestamp in its own clearly marked controls. A pause button controls the example timeline. A separate run control is appropriate only for a real run.

A useful comparison keeps the task fixed and varies one kind of presence at a time. Compare a receipt, a stationary target, and opt-in follow. Test whether people correctly predict what each control will do. Product documentation describes available mechanics and research studies test specific tasks, so record which parts of the new experience still need validation.
