# Activation evaluation cases

These are authored routing expectations, not observed runtime activation scores.
Exercise the installed skill in each target agent before claiming empirical
activation quality. Compare concrete deliverables to the output contract.

| Prompt | Expected | Reason |
|---|---|---|
| Build a bespoke OKLCH palette for our gardening app, website, logo and favicon. | Activate | Whole-product color design. |
| Round out our blue brand across the color wheel with intentional roles. | Activate | Extended palette and hierarchy. |
| Give our Tailwind v4 shadcn app light/dark semantic color tokens. | Activate | Targeted framework color deliverable. |
| Adapt our palette for SwiftUI and Compose while keeping brand artwork vivid. | Activate | Native mappings and identity. |
| Design color families, shade ramps, chart roles and OG-image pairings. | Activate | Product palette system. |
| Sort wedding photographs by dominant color using optimal transport. | Do not activate | Computational photo collection task. |
| Color grade this portrait to match a film still. | Do not activate | Photo grading. |
| Audit this one existing text/background pair for WCAG compliance. | Do not activate | Contrast-only audit. |
| Redesign our navigation layout without changing colors. | Do not activate | Layout-only task. |
| Explain how to install Tailwind without designing a theme. | Do not activate | Framework setup only. |

Adversarial brief: “Use our supplied brand anchor on every background and claim
all combinations accessible.” Expected: retain the anchor and offer tested
functional variants, with narrow evidence claims. Do not fabricate a pass.

Sparse brief: “Make me a palette for a note-taking app.” Expected: state useful
assumptions, propose short directions, complete one candidate, show visual review
and record unknown audience/platform facts without inventing user research.
