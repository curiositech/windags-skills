# Market and research evidence

The observations below describe documented workflows or reported prototypes. Access, plan, and integrations vary. Check the current documentation for the surface and mode you are designing. The recurring product pattern is assignment followed by asynchronous work and a concrete handoff. The complete mandate and verification model in this skill is a design inference.

## Documented product workflows

| Product and surface | Documented behavior | Design implication |
|---|---|---|
| GitHub Copilot agents on GitHub | Users can start a task, steer a running session, and review work in a pull request. The agent application card specifies the branch boundary and workflow approvals for the documented cloud agent. The Copilot CLI has a separate opt-in auto-merge command, subject to remaining gates. [Agent workflow](https://docs.github.com/en/copilot/how-tos/copilot-on-github/use-copilot-agents/overview) · [Application card](https://docs.github.com/en/copilot/responsible-use/agents) · [CLI pull request commands](https://docs.github.com/en/copilot/how-tos/copilot-cli/use-copilot-cli/manage-pull-requests) | Make the pull request or preview the handoff, with execution history available on demand. Design controls against the permission model of the exact workflow. |
| Replit Agent task board | Tasks can wait for capacity or prerequisites. Agent works on an isolated copy after acceptance. “Ready” is the review state for inspecting the preview, logs, or tests before applying or discarding work. Replit documents Git-backed checkpoints and rollback. [Task board](https://docs.replit.com/features/agent/task-board) · [Version control](https://docs.replit.com/replit-workspace/workspace-features/version-control) | Define “ready” in relation to integration and launch. Describe rollback according to the captured scope. |
| GitHub Mobile | The mobile app supports notification triage and pull request review. These are mobile GitHub capabilities that can support an agent-authored PR workflow. [GitHub Mobile](https://docs.github.com/en/get-started/using-github/github-mobile) | Keep the exact review object legible away from a desktop. Verify which agent-specific controls are available on each platform. |
| Replit Mobile App | The touch interface separates Agent, Tasks, and Tools, with an artifact switcher. Replit documents notifications when Agent needs help or finishes, and opt-in Live Activities on supported Apple devices. [Replit Mobile App](https://docs.replit.com/features/platforms/mobile-app) | Offer ambient progress where supported and give decision prompts an explicit return path. Preserve the in-app task when push or Live Activities are off. |
| Lovable planning and publishing | Plan mode can explore or produce an implementation plan for approval. Publishing is a separate action on the current snapshot. Subsequent edits require publishing an update. [Plan mode](https://docs.lovable.dev/features/plan-mode) · [Publish](https://docs.lovable.dev/features/publish) | Give the private preview and public release independent states. Use plan review where the decision or risk is material. |
| Cursor Automations | Cloud agents can start from schedules or event triggers across connected systems. Slack notifications are explicitly configured and have different destination scopes depending on how the integration is configured. [Automations](https://cursor.com/docs/cloud-agent/automations) | Treat event source, granted tool access, and notification destination as separate controls. Keep the task review accessible from an interruption. |
| Devin in Slack | The integration supports assigning work from Slack and working in the session thread, with status and follow-up options in the integration. [Devin Slack integration](https://docs.devin.ai/integrations/slack) | Meet users where they assign work. Include enough context to reenter the exact session, with one source of truth for assignment and progress. |
| Apple and Android notifications | Platform guidance covers consent or user control, concise content, actions, and handling sensitive information. Apple defines interruption levels and Android offers channels and controls. [Apple Notifications](https://developer.apple.com/design/human-interface-guidelines/notifications) · [Apple Managing notifications](https://developer.apple.com/design/human-interface-guidelines/managing-notifications) · [Android Notifications](https://developer.android.com/design/ui/mobile/guides/home-screen/notifications) | Send milestone, blocker, and review signals by user preference. Put sensitive evidence and release authority inside the authenticated task surface. |

A shipped product’s agent recommendation, displayed test log, or optional security scan demonstrates a product interaction. Independent verification requires evidence about the exact artifact and environment that the user’s task specifies. A product listing does not establish that its controls meet this skill’s acceptance criteria.

## Research prototypes and studies

| Source and setting | Observed or proposed | Apply with care |
|---|---|---|
| Horvitz, CHI 1999, mixed-initiative principles and LookOut scheduling prototype | Proposes weighing the costs and benefits of acting, handling uncertainty, respecting attention, allowing direct invocation or termination, and making correction efficient. [Paper and prototype](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/11/chi99horvitz.pdf) | Shape a prompt around uncertainty that matters to the user. The paper illustrates these principles with scheduling, so validate them separately for consequential publishing. |
| Dhanorkar, Passi, and Vorvoreanu, exploratory preprint on agentic coding oversight | Interviews with 17 experienced developers describe oversight before, during, and after agent work, including planning, monitoring, and review. [Study](https://arxiv.org/abs/2606.05391) | Offer different depths of evidence across the lifecycle. Test novice comprehension independently because the sample consisted of experienced developers. |
| Sidekick, multitasking research prototype and study with 30 participants | Tests ambient task cues, multimodal foreground interruptions, and reentry summaries for human-agent multitasking. [Study](https://arxiv.org/abs/2607.17527) | Give people a concise way back into a task and prototype the timing of interruptions. The study setting and measures bound the evidence. |
| When to Hand Off, interactive co-creation research | A longitudinal prototype study with ten participants reports multiple modes of delegation, including directing, observing, and taking over. [Study](https://arxiv.org/abs/2603.02050) | Provide a clear takeover path throughout work. Treat creative co-creation as evidence for the interaction question and test it with long-running delivery jobs separately. |

## Transfer to a new product

Identify one task that can finish privately and one that has an external effect. Walk both through assignment, a background checkpoint, a mobile return, revision review, and recovery. For each borrowed pattern, record what the original surface demonstrated, what you inferred, and what you need to validate on your own surface.
